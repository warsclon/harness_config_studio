# Saves use revisions and atomic replacement

Web Management never writes a Pending Edit directly over an unchecked file: Save Review must be explicitly approved, the current bytes must still match the opened Edit Revision, and both Artifact Backup creation and retention enforcement must succeed first. A retry reuses a backup for the same Artifact Identity and Edit Revision rather than generating duplicates; if retention still fails, the original remains unchanged. The replacement is written through an unmistakably app-owned temporary file in the same directory, preserves permissions and existing formatting choices, and becomes visible atomically; any failed precondition or write step leaves the original intact. For a symbolic-link artifact, the backup is associated with the link's Artifact Identity, records its Resolved Path, and protects the target bytes; a missing file or changed link target is a conflict rather than permission to recreate it. App-owned sibling temporaries older than 24 hours are removed only when that same artifact is opened again, never by a broad Workspace sweep. Save is disabled without a Pending Edit, and Save Review rejects edited content above one MiB even when the originally opened file was smaller.
