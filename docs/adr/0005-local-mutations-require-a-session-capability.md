# Local mutations require a session capability

Binding Web Management to loopback is not sufficient once it can mutate or expose file content, because an unrelated browser origin may still attempt requests to local services. Every content-bearing or mutable request therefore requires a random in-memory, per-process session capability plus strict Origin and Host validation, and fails closed when any check is absent or invalid. The server also revalidates path, scope, kind, symbolic-link state, permissions, format, and action eligibility immediately before acting; browser-supplied paths are never authoritative. This protects against unrelated browser origins, not a hostile process already running as the same macOS user, which remains inside v1's trusted local-user boundary.
